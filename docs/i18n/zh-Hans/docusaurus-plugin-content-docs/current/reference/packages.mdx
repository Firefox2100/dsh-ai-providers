## `@dsh-ai-providers/core`

提供嵌入、重排、语音、图像、提供方、调用选项和统一错误的公共接口。使用方和提供方插件都应从此包导入共享类型。

## `@dsh-ai-providers/openai-compatible`

提供 OpenAI 兼容协议的传输、请求序列化、流解析、连接校验及服务实现。它没有 DSH 插件入口；OpenAI 与 LocalAI 插件通过组合使用它，彼此不产生依赖。

## `@dsh-ai-providers/runtime`

运行时协调插件，提供注册表、所选能力服务、设置及认证配置 API、健康检查、DSH 语言模型路由、并发调度和嵌入去重。

## `@dsh-ai-providers/openai`

提供 OpenAI 兼容的嵌入、语言模型对话与流、TTS、文件与实时 STT，以及图像生成。兼容服务器可能只实现其中一部分；应只启用并选择服务器实际提供的能力。

端点和配置请参阅 [OpenAI 兼容](../official-providers/openai)。

### `@dsh-ai-providers/localai`

LocalAI 专用提供方，涵盖语言模型、嵌入、重排、TTS、文件及实时 STT 和图像生成。它复用经过测试的 OpenAI 兼容传输层，同时加入 LocalAI 默认值、原生请求字段和重排。

配置与原生控制项请参阅 [LocalAI](../official-providers/localai)。

## `@dsh-ai-providers/jina-cohere`

实现 Jina 和 Cohere 兼容的 `/rerank` API。连接与凭据的复用方式和 OpenAI 连接一致。

配置与兼容细节请参阅 [Jina 与 Cohere](../official-providers/jina-cohere)。

## `@dsh-ai-providers/anthropic`

Anthropic 原生 Messages API 提供方，提供带流式文本、思考、工具调用、图像输入、用量报告和模型发现的语言模型路由。

配置与原生 API 行为请参阅 [Anthropic](../official-providers/anthropic)。

## `@dsh-ai-providers/all`

仅含元数据的 DSH 软件包组合，用于安装运行时及四个由本项目维护的提供方插件。

## 选择依赖

| 构建目标 | 应依赖 | 无需依赖 |
| --- | --- | --- |
| 使用 AI 能力的插件 | `@dsh-ai-providers/core` | 特定厂商包 |
| 第三方提供方插件 | `@dsh-ai-providers/core`，并以运行时作为 DSH 宿主 | 另一厂商包 |
| 使用 OpenAI 传输格式的提供方实现 | `@dsh-ai-providers/openai-compatible` 与核心契约 | `@dsh-ai-providers/openai` |
| 使用全部项目维护提供方的配置档案 | `@dsh-ai-providers/all` | 各包的单独安装命令 |
| 只使用部分提供方的配置档案 | 运行时及所需厂商包 | 全提供方整合包 |

使用方代码应始终把 `core` 作为公共类型边界。运行时内部实现和传输辅助代码可能因实现需求而变化；使用方直接导入它们，会重新制造本项目试图消除的耦合。

## 整合包与库包

运行时和四个厂商包是带有整合元数据的 DSH 插件。`core` 与 `openai-compatible` 是库：它们作为依赖安装，不是用户在配置档案中启用的行。`all` 只包含整合元数据，不会增加另一层运行时实现，因此不会引入重复服务层。

同一发行版中的所有公共包使用相同版本。直接声明多个依赖时应保持版本一致，尤其是针对共享契约编译的提供方实现。
