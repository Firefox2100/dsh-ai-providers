title: Jina 与 Cohere

`@dsh-ai-providers/jina-cohere` 实现 Jina AI、Cohere 共用的 `POST /rerank` 格式，也支持部分 LocalAI、vLLM 等兼容部署。它由 Firefox2100 在本项目中维护，不是 DSH、Jina AI 或 Cohere 官方软件包。

## 配置连接

创建一个或多个包含 ID、名称、基础 URL 和 DSH 凭据引用的连接。默认配置为：

![DSH 设置中的 Jina 或 Cohere 兼容重排连接](/img/screenshots/providers/jina-cohere-settings.png)

| 设置 | 默认值 |
| --- | --- |
| 基础 URL | `https://api.jina.ai/v1` |
| 凭据引用 | `JINA_API_KEY` |
| 模型 | `jina-reranker-v2-base-multilingual` |
| 超时 | 60 秒 |

使用 Cohere 或其他兼容服务器时，更改基础 URL、凭据引用和模型。基础 URL 应为 `/rerank` 之前的路径前缀。

随后打开重排能力标签页，选择 **Jina / Cohere compatible** 作为活动提供方。

## 兼容行为

请求包含 `model`、`query`、`documents`、可选 `top_n` 及 `return_documents: false`。响应可使用 `relevance_score` 或 `score`；如存在 Jina 或 Cohere 风格的 token 用量字段，服务也会读取它。

服务会拒绝空问题和空文档，按分数降序排列结果，并将原始 logit 归一化到服务接口规定的 0 到 1 范围。

## 连接边界

当端点需要不同凭据、超时或基础 URL 时，应使用独立连接。连接 ID 是配置身份；一旦其他能力或配置档案设置引用它，就应保持稳定。凭据引用指向由 DSH 管理的密钥，并不是密钥值本身。

自托管服务器可以留空凭据引用。只有明确受信任的本地部署才应使用 HTTP 基础 URL；公共服务应使用 HTTPS。提供方会追加 `/rerank`，因此基础 URL 若已经包含该端点，会导致路径重复。

## 响应要求

每项结果必须通过索引指向对应的输入文档。索引超出候选列表、缺少分数或分数不是数值，都属于异常响应；调用会失败，而不会静默接受。规范化结果不返回文档正文，因为使用方已经持有它们。

Jina 与 Cohere 并不保证模型、限制或分数校准一致。模型 ID 应视为提供方专属；候选集应保持在所选服务限制内；分数只在同一次响应中比较。

## 诊断兼容性

服务器拒绝请求时，先检查配置的路径前缀和模型，再将其 `/rerank` 请求格式与上述字段比较。认证、配额和未知模型响应会成为 `rejected`；连接和服务器失败成为 `unavailable`；调用方输入异常为 `invalid-input`。

使用示例请参阅[重排](../services/reranking)。
