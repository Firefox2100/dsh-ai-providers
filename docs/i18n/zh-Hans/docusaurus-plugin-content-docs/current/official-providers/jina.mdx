`@dsh-ai-providers/jina` 是 Firefox2100 在本项目中维护的 Jina AI 提供方，提供重排和嵌入。它不是 DSH 或 Jina AI 官方软件包。

## 支持能力

| 能力 | 端点 |
| --- | --- |
| 重排 | `POST {基础 URL}/rerank` |
| 嵌入 | `POST {基础 URL}/embeddings` |

这套重排 API 由 Cohere 首创，Jina、vLLM 等随后沿用，因此遵循它的服务器也可以通过自定义基础 URL 使用本提供方。传输层位于库软件包 `@dsh-ai-providers/jina-cohere`，本提供方与 [Cohere](./cohere) 提供方都使用它，彼此之间没有依赖。

## 配置连接

在 **设置 > 提供方 > Jina 连接** 中创建一个或多个连接，包含标识、名称、基础 URL 和 DSH 凭据引用。默认值为：

![DSH 设置中的 Jina 连接与凭据引用](/img/screenshots/providers/jina-settings.png)

| 设置 | 默认值 |
| --- | --- |
| 基础 URL | `https://api.jina.ai/v1` |
| 凭据引用 | `JINA_API_KEY` |
| 重排模型 | `jina-reranker-v2-base-multilingual` |
| 嵌入模型 | `jina-embeddings-v3` |
| 超时 | 60 秒 |

随后打开“重排序”或“嵌入”能力标签页，选择 **Jina** 作为活动提供方。端点需要不同凭据或基础 URL 时请使用不同连接；连接标识是配置身份，被选择项引用后应保持稳定。凭据引用是 DSH 管理的密钥名称，而不是密钥本身。自托管服务器可以留空。提供方会自行追加 `/rerank` 或 `/embeddings`，因此基础 URL 中不要包含它们。

## 嵌入

使用方选择的“查询”或“文档”会作为 Jina 的 `task` 发送：`retrieval.query` 或 `retrieval.passage`；未作选择时不发送 task。请求选项 `task` 会覆盖这一选择，并接受模型的其他任务（`text-matching`、`classification`、`separation`）。

| 设置 | 请求字段 | 默认值 |
| --- | --- | --- |
| 向量维度 | `dimensions` | 0：由模型决定；也是会话第一次请求前就要选定的请求选项 |
| 超出输入长度的文本 | `truncate` | 截断 |
| 批大小 | 每次请求的文本数 | 64 |

不同长度或不同模型的向量无法比较，请在第一次请求前选定维度并保持模型不变。

## 重排

请求包含 `model`、`query`、`documents`、可选 `top_n` 及 `return_documents: false`。响应可使用 `relevance_score` 或 `score`，有用量信息时会读取。服务会拒绝空查询和空文档，按分数从高到低排序，并用 logistic 函数把超出 0 到 1 的原始分数归一化，同时保持其顺序。

Jina 的重排接口除 `top_n` 和 `return_documents` 外没有其他参数，因此该提供方不描述重排请求选项。`jina-reranker-m0` 还能对图像排序，但重排契约只承载文本，所以文档始终是文本。

每条结果都必须用索引指明对应的输入文档。超出候选列表的索引、缺失或非数值分数都属于格式错误，会使调用失败。Jina 与 Cohere 并不保证模型、限制或分数校准一致：候选集应保持在服务限制内，分数只应在同一次响应内比较。

## 诊断兼容性

服务器拒绝请求时，先检查配置的路径前缀和模型，再将其请求格式与上述字段比较。认证、配额和未知模型响应会成为 `rejected`；连接和服务器失败成为 `unavailable`；调用方输入异常为 `invalid-input`。

使用示例请参阅[重排](../services/reranking)和[嵌入](../services/embeddings)。
